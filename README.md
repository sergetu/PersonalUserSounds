# PersonalUserSounds

**PersonalUserSounds** — BetterDiscord-плагин для назначения персональных звуков отдельным пользователям Discord.

Идея простая: вместо одного стандартного уведомления Discord можно сразу по звуку понимать, **кто именно написал, позвонил, подключился или вышел из голосового канала**.

Например:

- одному человеку назначить выстрел винтовки на сообщение;
- другому — отдельную мелодию на входящий звонок;
- третьему включить `silent`, если уведомления от него звучат слишком часто;
- для остальных оставить стандартное поведение Discord.

Плагин изначально сделан для личного использования и развивается под реальные сценарии нескольких пользователей. Основной приоритет — не максимальное количество функций, а предсказуемое поведение: **если плагин не может надёжно определить пользователя или безопасно заменить звук, он предпочитает оставить стандартное поведение Discord**.

Начиная с версии **1.1.0**, интерфейс отделён от основной логики плагина. UI можно запускать отдельно в обычном браузере, а сборщик дополнительно проверяет, что при рефакторинге интерфейса не была случайно изменена звуковая логика.

---

## Возможности

Для каждого пользователя можно отдельно настроить звуки следующих событий:

- новое сообщение;
- входящий звонок;
- выход из общего голосового канала;
- подключение к голосовому каналу.

Для каждого события доступны четыре режима:

| Режим | Поведение |
|---|---|
| `inherit` | Использовать глобальную настройку этого события |
| `default` | Не воспроизводить персональный звук и оставить стандартное поведение Discord |
| `custom` | По возможности заменить стандартный звук выбранным аудиофайлом |
| `silent` | Подавить звук события, если плагин может надёжно его перехватить |

Также доступны:

- глобальная громкость;
- отдельная громкость каждого события;
- учёт режима Discord **Не беспокоить**;
- учёт **Streamer Mode**;
- настройка воспроизведения уведомлений в открытом активном канале;
- замена стандартных звуков Discord вместо одновременного воспроизведения;
- задержка между звуками сообщений одного пользователя;
- несколько режимов обработки сообщений;
- встроенная диагностика аудиофайлов;
- проверка совместимости используемых внутренних Discord-модулей;
- режим отладки;
- русская и английская локализация интерфейса.

## Установка

### 1. Установите BetterDiscord

Плагин предназначен для **Discord Stable + BetterDiscord**.

### 2. Возьмите готовый файл

Для установки используйте:

`dist/PersonalUserSounds.plugin.js`

### 3. Скопируйте его в папку BetterDiscord

```text
%APPDATA%\BetterDiscord\plugins
```

### 4. Включите плагин

Перезапустите Discord либо откройте:

```text
Настройки Discord
→ BetterDiscord
→ Plugins
→ PersonalUserSounds
```

и включите плагин.

### Зависимости

Дополнительные библиотеки не требуются.

Плагин не зависит от:

- ZeresPluginLibrary;
- BDFDB;
- удалённых JavaScript-библиотек.

## Настройка

Основные параметры находятся в настройках плагина.

### Общие параметры

Можно настроить:

- включение или отключение персональных звуков;
- глобальную громкость;
- учёт режима `Do Not Disturb`;
- учёт `Streamer Mode`;
- воспроизведение в активном открытом канале;
- замену стандартных звуков Discord;
- cooldown между уведомлениями одного пользователя;
- режим обработки сообщений;
- режим отладки.

### Режимы обработки сообщений

Доступны три варианта:

#### `follow_discord`

Плагин старается следовать обычным правилам уведомлений Discord, включая состояние канала, mute-настройки, mentions и активный открытый канал.

#### `direct_messages`

Персональные звуки сообщений используются прежде всего для личных сообщений.

#### `all_messages`

Плагин обрабатывает сообщения шире, независимо от стандартного сценария DM.

## Добавление пользователя

Настроить пользователя можно двумя способами.

### Через контекстное меню

Нажмите правой кнопкой мыши на пользователя и выберите:

```text
Персональные звуки
```

### Через User ID

User ID можно добавить вручную в настройках PersonalUserSounds.

Пользователь должен быть доступен в локальном `UserStore` Discord.

Если пункт контекстного меню не появляется после обновления Discord, можно использовать добавление по User ID как резервный вариант.

---

## Пользовательские звуки

Для каждого пользователя отдельно настраиваются:

- `message`;
- `incomingCall`;
- `disconnect`;
- `voiceJoin`.

Каждое событие имеет:

- режим;
- аудиофайл;
- индивидуальную громкость.

При выборе файла через интерфейс плагин сохраняет аудиоисточник вместе с настройками, а отображаемое имя или путь файла хранится отдельно для удобства пользователя.

Встроенные кнопки **Прослушать** и **Диагностика** позволяют проверить файл до использования.

Если Discord не может декодировать выбранный формат, рекомендуется попробовать обычный `.mp3` или `.wav`.

## Безопасность и приватность

PersonalUserSounds работает локально внутри Discord/BetterDiscord.

Плагин:

- не использует Discord REST API;
- не запрашивает и не читает пользовательский токен Discord;
- не сохраняет содержимое сообщений;
- не логирует текст сообщений;
- не загружает во время работы сторонний код или JavaScript-библиотеки из интернета.

Для определения событий используются BetterDiscord API и внутренние модули клиента Discord.

> Внутренние Discord-модули не являются стабильным публичным API и могут измениться после обновления клиента.

Для таких случаев в плагине предусмотрена встроенная проверка совместимости.

## Ограничения

Discord не предоставляет стабильный публичный API для всех событий, которые необходимы PersonalUserSounds. Поэтому часть функций зависит от внутренних модулей клиента.

Из этого следуют несколько ограничений.

### Group DM

Для входящего звонка в Group DM персональный звук применяется только тогда, когда инициатора звонка можно определить достаточно надёжно.

Если это невозможно, плагин оставляет стандартное поведение Discord.

### Подавление стандартных звуков

Режимы `custom` и `silent` могут полностью заменить стандартный звук только в тех местах, где событие удалось надёжно перехватить.

### Обновления Discord

После крупных обновлений Discord некоторые внутренние модули или методы могут измениться.

Если персональные звуки перестали работать:

1. откройте настройки PersonalUserSounds;
2. включите `Debug mode`;
3. нажмите **Проверить совместимость**;
4. проверьте состояние используемых модулей.

---

## Принцип fail-safe

В неоднозначной ситуации плагин предпочитает:

**оставить стандартный звук Discord**

вместо того, чтобы:

**проиграть персональный звук неправильного пользователя**.

Особенно это важно для:

- Group DM;
- входящих звонков;
- голосовых подключений;
- голосовых отключений;
- перемещений между голосовыми каналами.

---

## Обработка событий

Плагин использует несколько источников событий и резервные механизмы.

### Сообщения

Основной путь связан с системой desktop-уведомлений Discord.

При необходимости используется fallback через:

```text
MESSAGE_CREATE
```

### Входящие звонки

Основной путь — перехват стандартного звука:

```text
call_ringing
```

Дополнительные источники:

```text
CallStore
CALL_CREATE
CALL_UPDATE
CALL_DELETE
```

### Голосовые каналы

Состояние отслеживается через:

```text
VOICE_STATE_UPDATES
```

и сравнивается с предыдущим известным состоянием `VoiceStateStore`.

Изменения:

- mute;
- deaf;
- video;

сами по себе не считаются подключением или отключением пользователя.

При перемещении пользователя между голосовыми каналами плагин старается генерировать только одно соответствующее событие.

---

## Внутренние Discord-модули

Необходимые модули ищутся и кэшируются при запуске плагина. Повторный Webpack-поиск на каждое событие не выполняется.

Используются следующие внутренние компоненты:

### `UserStore`

Текущий пользователь и локальный поиск пользователей по User ID.

### `ChannelStore`

Данные каналов и получателей DM.

### `SelectedChannelStore`

Текущий открытый канал.

### `VoiceStateStore`

Состояние пользователей в голосовых каналах.

### `CallStore`

Состояние Discord-звонков и резервное определение изменений звонка.

### `RelationshipStore`

Проверка отношений между пользователями, включая блокировки.

### `StreamerModeStore`

Состояние Streamer Mode.

### `StatusStore`

Best-effort определение режима `Do Not Disturb`.

### `Dispatcher`

Получение внутренних событий Discord.

Используется доступный Dispatcher через Discord-модули с резервным поиском объекта, содержащего:

```text
subscribe
unsubscribe
dispatch
```

### `DesktopNotification`

Используется для обработки desktop-уведомлений Discord.

### `SoundUtils`

Используется для взаимодействия со штатной системой звуков Discord.

---

## Очистка ресурсов

При отключении PersonalUserSounds плагин очищает созданное им состояние:

- подписки на Dispatcher;
- patches;
- timers;
- активные `Audio`-объекты;
- loop-звуки входящих звонков;
- UI-обработчики.

Повторное включение плагина не должно создавать дублирующиеся подписки или несколько экземпляров одного обработчика.

---

## Проверка работоспособности

Основные сценарии, которые следует проверить после существенных изменений плагина или обновлений Discord:

- настроенный пользователь отправляет DM → воспроизводится его `custom`-звук;
- ненастроенный пользователь → сохраняется стандартное поведение Discord;
- `default` → персональный звук не воспроизводится;
- `silent` → звук подавляется там, где событие можно надёжно перехватить;
- собственные сообщения игнорируются;
- `follow_discord` учитывает обычные правила уведомлений Discord;
- серия быстрых сообщений одного пользователя не превращается в «звуковой пулемёт»;
- входящий звонок настроенного пользователя запускает loop-звук;
- принятие, отклонение или отмена звонка останавливает loop;
- Group DM не назначается случайному участнику;
- выход настроенного пользователя из общего голосового канала создаёт событие отключения;
- mute/deaf/video не создают ложное событие отключения;
- перемещение пользователя между каналами не создаёт дублирующиеся события;
- отключение текущего пользователя не воспроизводит звуки остальных участников;
- после выключения плагина его подписки, патчи, таймеры и аудио освобождаются;
- повреждённый или отсутствующий аудиофайл не приводит к падению плагина;
- повторное включение не создаёт дублирующиеся подписки;
- в консоли нет необработанных `Promise rejection`.

# Разработка

Начиная с версии **1.1.0**, пользовательский интерфейс отделён от основной логики PersonalUserSounds.

Цель такого разделения — возможность менять и тестировать интерфейс, не вмешиваясь без необходимости в код обработки Discord-событий и звуков.

## Структура проекта

```text
PersonalUserSounds/
├── PersonalUserSounds.plugin.js
├── README.md
├── SPEC.md
│
├── src/
│   └── plugin.js
│
├── ui/
│   └── panel.html
│
├── tools/
│   ├── build.js
│   └── transform.js
│
└── dist/
    └── PersonalUserSounds.plugin.js
```

---

## `src/plugin.js`

Основная логика BetterDiscord-плагина.

UI-зависимые методы сведены к тонкому слою взаимодействия с `PussUI`.

Основная логика обработки:

- сообщений;
- звонков;
- голосовых состояний;
- звуков;
- Discord-модулей;

отделена от реализации интерфейса.

---

## `ui/panel.html`

Единый источник пользовательского интерфейса.

Файл содержит:

- CSS;
- HTML-шаблоны;
- русскую и английскую локализацию;
- UI-логику `PussUI`;
- браузерный preview-режим.

Используются CSS-переменные Discord:

```css
var(--...)
```

поэтому внутри Discord интерфейс наследует текущую тему.

### Browser Preview

`ui/panel.html` можно открыть обычным браузером без Discord.

В preview-режиме используются демонстрационные данные.

Можно проверить:

- русскую и английскую локализацию;
- светлую и тёмную тему;
- панель настроек;
- редактор пользователя;
- справку;
- диагностику;
- окно совместимости;
- адаптивность интерфейса.

Это позволяет отлаживать визуальную часть отдельно от BetterDiscord.

---

## `tools/transform.js`

Служебный инструмент механического преобразования исходного плагина в архитектуру с вынесенным UI.

Используется при необходимости повторного получения `src/plugin.js` из исходной версии плагина.

---

## `tools/build.js`

Собирает:

```text
src/plugin.js
+
ui/panel.html
↓
dist/PersonalUserSounds.plugin.js
```

Во время сборки UI инлайнится внутрь конечного `.plugin.js`, поэтому установленный BetterDiscord-плагин остаётся одним самостоятельным файлом.

### Сборка

Из корня репозитория:

```bash
node tools/build.js
```

Результат:

```text
dist/PersonalUserSounds.plugin.js
```

---

## Проверки сборки

Сборщик выполняет несколько проверок.

### Синтаксис

```bash
node --check dist/PersonalUserSounds.plugin.js
```

### Структура

Проверяется наличие необходимых маркеров собранного плагина и UI-шаблонов.

### Проверка логики

Не-визуальные методы сравниваются с эталонной версией, чтобы изменение UI не привело к незаметному изменению основной логики.

Цель проверки:

```text
UI изменился
≠
логика обработки Discord-событий изменилась
```

При чистом UI-рефакторинге не-визуальная логика должна оставаться идентичной.

---

## Развёртывание

После успешной сборки скопируйте:

```text
dist/PersonalUserSounds.plugin.js
```

в:

```text
%APPDATA%\BetterDiscord\plugins
```

Перед заменой используемой версии рекомендуется сохранить резервную копию текущего файла.

Сам `build.js` установленный плагин автоматически не заменяет.

## Статус проекта

PersonalUserSounds — небольшой независимый проект, созданный прежде всего для личного использования.

Он зависит от внутренних модулей Discord, поэтому абсолютная совместимость со всеми будущими версиями клиента не гарантируется.

При этом архитектура специально построена так, чтобы изменения Discord было проще диагностировать, а изменения интерфейса — проверять отдельно от основной логики.
